2 AI: The Topic Every Customer Wants to Talk About Today

This is the part I give the most time to in the conversation — because it’s what’s on the mind of every CTO, VP Engineering, and CISO I meet in 2026.


"I want to pause for a moment and talk about AI, because today it’s really a turning point for almost every organization. AI doesn’t change these five stages — it just massively increases the speed at which you move through them. And when speed goes up, every crack that already existed gets bigger, and faster."
Speed vs. Quality

"Your developers are already using tools like Copilot or Cursor to write code — and that’s great for speed. The problem is that testing throughput doesn’t grow at the same pace. You get more code, but not more verification that it’s correct. And that’s exactly the gap that causes the spike in bugs reaching production."

APIs Built for Humans, Not AI Agents

"Here's a point most companies don't think about at all: when an AI agent is the one consuming your API instead of a human developer, it needs a different kind of spec. An AI agent doesn't 'understand from context' like a developer does — it needs to be told explicitly which actions are possible and what their constraints are. If your API isn't written that way, the agent will simply misuse it — and you won't know until it happens in production."

Governance as the Bottleneck

"And when everything runs faster, Governance and security become the organization's bottleneck. Audit evidence documentation turns from an ongoing process into a manual scramble once a quarter. And nobody wants to do that under pressure."

A Stat I Open With

"89 percent of developers already use AI to write code. Only 24 percent of them even design their API so that an AI agent will know how to use it correctly. That's the gap we close."

How I continue into the AI part of our own product "And that brings me to the point our customers love the most: the AI inside Postman isn't like a general ChatGPT. We call it Agent Mode, and it's built specifically for the API world.
It runs inside your Postman environment, knows all the projects, tests, and alerts you already have, and doesn't just answer questions but actually takes action: writes new contracts, fixes broken tests, and detects when a new version breaks a promise you made to someone in the past.

There's also AI Engineer, which connects to wherever all your code and its history is kept (Git) and does more independent work.
For example, going through all your APIs and flagging which ones should be deprecated because they're old or unused, or automatically checking every new code change a developer pushes to the system, before it's merged.
And you can also build the Governance rules themselves with the help of AI — write them in Claude or ChatGPT, and Postman is what actually enforces them automatically, across every project, all the time.
And that's really the real difference: you could do some of this yourselves, or buy several separate tools — but we put it all under one roof."

3 What We Have to Offer - Stage by Stage

"This is what I call the golden path: at every stage there’s a tool that automatically enforces what we defined in the previous stage - so you’re not checking it again later."

01 · Design

"You spec out ahead of time what the API is supposed to do — like a proper contract before you start actually building — and there’s AI that helps write and fix that contract. You can also set a rule like ‘every request must have identity verification,’ and it doesn’t stay a recommendation someone has to remember to check — it’s enforced automatically. And while the backend team is still building the real system, the frontend team can already start working against a simulated version that behaves like the real API (Mock Server), so they don’t have to wait."

02 · Development

"Every time a developer writes code, we have a tool running in the background that automatically checks the code still complies with the contract defined in the design stage — just like a spell-checker that runs while you write a document, except it checks logic instead of typos. And if someone changes something that’s about to break a promise someone else already relies on — it’s caught in that same moment, before the code even enters the product, unlike traditional testing where you find out two weeks later."

03 · Testing

"There’s a tool that automatically runs a whole suite of tests at the click of a button, and there’s an AI assistant that builds basic tests directly from the contract you wrote at the design stage, and even fixes a broken test. You can also test what happens under high load — for example what happens if there’s suddenly a lot more users, like on a big sale day."

04–05 · Deployment & Monitoring

"There are automated checks running constantly on the APIs facing the outside world, to make sure they’re actually responding and working. There’s a parallel version that runs inside your internal network, behind all the security layers, for APIs that aren’t open to the world. And Insights identifies gaps based on the actual real traffic happening in practice."

"Two things you should know — they don’t belong to one stage, they run across all of them:
API Catalog gives you a single view of every API in development across the organization — not just the ones already live on a gateway in production. That’s the key difference between us and Kong, Apigee, or Boomi — they show you only what’s already running, we also show you what’s being built.
And Agent Mode with AI Engineer are available at every stage — not general-purpose assistants, but tools that know your context and actually take action."

"This sounds like Waterfall — we work Agile / CD."
"These stages aren’t Waterfall gates — they’re quality activities that happen all the time. In a CD organization: every PR is ‘design,’ every merge is a ‘gate,’ every deploy to staging is ‘verification.’ The question isn’t whether these stages exist for you — the question is whether they’re connected, or fragmented."
"We already have QE and tools for that."
"So I ask: do your tools share artifacts between stages, or does each tool keep its own format? And can you pull an audit trail automatically, or is it a manual review every quarter?"

"If the agent that wrote the code is also the one that wrote the test, there’s a built-in conflict of interest — the test will reflect the assumptions of the implementation, not the intent of the spec. The question isn’t whether AI can generate tests — the question is whether the tests are independent, spec-based, and under Governance."

Fabric

Fabric is our central control layer for the AI world in the organization.

How I explain it "As more teams start using different models — OpenAI, Claude, Gemini — to build AI Agents, and connect to MCP servers and internal APIs, each team starts managing its own connections, permissions, and Credentials. Fabric centralizes all of that traffic through a single control point — so the organization knows where AI requests are being sent, which models and APIs they can access, how secrets are kept, how much it costs, and what actually happened."
What Fabric Enables for the Organization
  • Central Control Point — manage the traffic between models, Agents, MCP servers, and internal APIs from one place.
  • Routing and Reliability — route requests between models, perform automatic Fallback when a model goes down, and pick the right model for each request.
  • Security and Credential Management — the Agent doesn’t need to see or hold the keys itself.
  • Agent Governance — determine precisely which APIs, Tools, or MCP Servers each Agent is authorized to access.
  • Cost Control — see who’s consuming how many Tokens and at what cost, and set budgets.
  • Full Audit — know who activated which Agent, on which model, which API it accessed, and which Policy was triggered.
Example I give: You have a team working with OpenAI, another team with Claude, and an Agent connecting to an MCP Server — and they all need access to internal systems. Today each of them holds its own Keys, permissions, and logs, and there’s no central layer that sees all the traffic. With Fabric, all requests pass through a single control layer: if an Agent requests GPT-5, Fabric can approve, block, route to a different model, switch to Claude if there’s an outage, or split traffic between several models — all in one place.
Summary line "Fabric is the central control layer that connects the organization's AI, Agents, MCP servers, and APIs — and gives you control over traffic, security, permissions, costs, and Audit, instead of each of them being managed separately."
Postman Passport

Passport is a central Governance layer for discovering, requesting access to, and securely consuming APIs across the organization.

The challenge I describe "As there are more APIs and more people, applications, and AI Agents that need to use them, it becomes hard to know who’s using what, who has access, and where the API Keys and Secrets end up scattered. A developer looks for an API on Slack or in documentation, requests access from someone, and the real Key ends up in .env files, scripts, CI/CD, and other places. And as more AI Agents start accessing APIs, this challenge only grows."
Example I give: A new team is building an application that needs an internal customer API. The developer needs to figure out who owns it, who to ask, get a Key, and plug it into the system. Multiply that by dozens of APIs and hundreds of developers — and at some point the organization no longer knows who holds which Key, and which API they have access to.
How Passport Solves This
  • Central Discovery — developers and AI Agents find approved APIs in one place.
  • Controlled Access Request — instead of getting the real Key, they get a Passport Reference.
  • Secretless Consumption — the real Credential stays in the customer’s existing Vault, and is only resolved at the actual moment of the API call — without the user or the Agent ever seeing or copying it.
  • Full Visibility — who requested access, who approved it, and how the API is actually used.
  • Works With Existing Tools — complements HashiCorp, AWS Secrets Manager, 1Password, etc., doesn’t replace them.
Summary line "Passport gives the organization a central way to discover APIs, manage access to them, and enable secure use of them — without exposing the real Credentials."

Advanced Security Administration — ASA

ASA is the Add-on I bring to the table when we talk about security at Enterprise scale — a product that exists and is active today, sold as a separate charge on top of Enterprise.

How I explain it "Broadly, it gives the security team more precise control over who can log in, from where, and how their secrets are kept. Postman’s default is already secure, but ASA adds an additional control layer specific to Enterprise and to regulatory requirements like SOC 2, ISO, or PCI."
What’s Included in ASA
  • Domain Capture — automatic routing of logins by domain, so every employee logs into the correct organizational account without confusion between personal and company accounts.
  • Secret Scanner — Dashboard & Alerts — not just a single secrets scanner, but an organization-wide picture: how many exposure attempts happened, where, and who was involved.
  • Integration With External Vaults — Azure Key Vault, HashiCorp, AWS Secrets Manager, 1Password — so Postman works with the infrastructure the customer already uses, rather than replacing it.
  • BYOK — Encryption With the Customer’s Own Key — the customer fully controls the encryption key; Postman never gets access to it at any stage.
Example I give: A financial organization subject to a regulation that requires it to encrypt all its sensitive data with a key it controls itself, and doesn’t rely on any external vendor holding the key. With BYOK, the organization keeps the encryption key in its own vault — and Postman simply cannot access the data without that key, even if it wanted to.
Summary line "ASA doesn't replace Postman's baseline security — it adds a layer of control, visibility, and control at the Enterprise level, for those who need to meet strict regulatory requirements."
