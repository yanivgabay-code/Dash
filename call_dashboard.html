"Why pay $49 when Team is only $19?"▶

Companies don't buy Enterprise because developers need more features - they buy it because the organization needs governance, security and control.

Bruno & Insomnia - "why not just use the free client?" (Nestlé case study)▶

The core distinction: a client handles step 1. An API only becomes valuable at steps 2 and 3.

  • Step 1 - Test: Bruno and Insomnia are genuinely fine here - so is Postman.
  • Step 2 - Share: Bruno only shares via Git, so anyone outside the repo is left out. Insomnia shares inside its own projects, but only to people already invited - no catalog, so nobody finds you on their own.
  • Step 3 - Combine: Bruno leans on vars/scripts you write yourself; Insomnia has response template tags but it's still hand-wired, one request at a time. Postman has Flows - a visual, cross-protocol builder.

Producers vs. consumers - Bruno and Insomnia serve the producer (you and your team, who have repo/invite access). They don't serve the consumer side: QA, integration devs, PMs, security reviewers, technical writers, external partners - most of whom aren't in your Git repo and don't know which of thousands of repos to dig through.

Real proof point - Nestlé: before consolidating, Nestlé ran ~200 fragmented Postman instances with no shared standards, ~2,000 accounts outside any control (personal domains, no SSO), inconsistent quality with no audit trail across any of the 200 instances, and unmanaged public link sharing. Moving to one Postman Enterprise instance gave them domain capture (auto-join for nestle.com sign-ups), SSO/SCIM/user groups, one API Catalog and Private API Network as the single source of truth, and central control over what goes public.

Postman isn't replacing their MuleSoft, SAP APIM, Kafka, or IBM MQ - it sits as a neutral layer on top that governs, documents, discovers, and tests across all of it.

Team vs Enterprise - In Plain Language

Team is a collaboration tool: developers share collections, build APIs together, test APIs, generate documentation. Perfect for one team.

Enterprise is an organizational platform: leadership can govern APIs, secure APIs, standardize development, discover APIs, measure adoption, control thousands of users, and support compliance. Perfect for many teams.

Example: in Team, the Platform Team can't see what Backend built - APIs get duplicated, no governance, no enterprise visibility. In Enterprise, every API is discoverable, standards are enforced, architects have visibility, security knows who owns every API, and Platform Engineering manages it all centrally.

Enterprise Feature Explanations (objection → answer)

Private API Network▶

Private API Network = "What APIs do we have, and can I reuse one?"

  • Gives developers one place to find and discover internal APIs.
  • They can search, see who owns an API, read the documentation, and reuse it instead of building something from scratch.
  • Think of it as an internal App Store for APIs.

Basically, it's like a live directory of all your APIs that updates itself automatically.

Instead of a wiki that someone has to keep updating, it always shows what your teams are actually using. Developers can search for an API, see who owns it, reuse an existing one instead of building it from scratch, and get started quickly.

And there's a Network Manager who makes sure only the right APIs get added, so the whole thing stays clean and useful.

API Catalog▶

Postman API Catalog is a centralized place to see, monitor, and govern the APIs across your organization. It gives teams visibility into API health, security, ownership, quality, and compliance, helping them identify and address issues early.

You can think of the API Catalog as the engineering intelligence layer on top: it ingests CLI runs, CI/CD pipelines and spec-linting results into a dashboard showing health, quality and compliance posture across every API, with scorecards you define yourself.

API Catalog = "How are our APIs doing?"

  • Monitors APIs across the organization.
  • Shows health, security, quality, ownership, and compliance.
  • Helps teams identify problems and enforce API standards.
  • Think of it as an API health and governance dashboard.

Private API Network helps you FIND and REUSE APIs.
API Catalog helps you MONITOR and GOVERN APIs.

They work well together: a developer can find an API in the Private API Network, while the platform team can use the API Catalog to understand whether that API is healthy, secure, and compliant.

Postman Passport (Early Access)▶
ProspectWe're starting to let AI agents call our internal APIs - how do we stop that from turning into secrets sprawl?
AEThat's exactly what Passport solves. Developers and agents never hold the real secret - they get a secret reference instead. A Proxy container that runs inside your own cloud resolves the real credential at call time, so the secret never touches a laptop, a config file, a log, or an agent's context. Access is granted per identity and per API, every call is logged back to who requested it, and you can revoke access instantly without rotating anything.

Contains the risk (real secrets never leave your cloud, and Postman's own cloud is never in the request path), gives granular per-identity/per-API control, keeps developer and agent workflows unchanged (same reference works from terminal, IDE, CI, or an agent), and plugs into the secret store you already run - HashiCorp Vault and AWS Secrets Manager today.

30-second pitch - say this on a call

"Today, calling an API means someone - or something - has to hold the real secret, and the moment it does, it's already leaking into logs, config files, and now AI agent contexts faster than anyone can rotate or detect. Postman Passport removes that requirement entirely: developers and agents get a secret reference instead of the real credential, a proxy running inside your own cloud resolves it at call time, and every call is logged and revocable in one click - same workflow, same tools, the real secret just never leaves your infrastructure."

Example line: "If an agent's context got leaked tomorrow, would a real API secret leak with it? Passport is built so the answer is no."

Early Access - requires a Secret Store (Vault or AWS Secrets Manager) and a container to run the Passport Proxy in the customer's own cloud.

Advanced Security Administration (ASA) - the Enterprise add-on

Pitch angle: base Enterprise gives you control over what your licensed users do. ASA gives you control over the shadow usage you don't even know about yet.

  • Domain Capture - any user who signs up with your company email is automatically routed into your managed org; existing and new free accounts under your domain are prompted to request access, giving admins full control and visibility
  • Account Discovery - detects Postman usage across your corporate network regardless of which email address someone used to sign up
  • Account Control - apply policies to report or block unmanaged personal accounts and enforce the corporate Postman experience
  • Postman Vault integrations - connect to AWS Secrets Manager, Azure Key Vault or HashiCorp Vault so secrets are never stored in Postman itself
  • Advanced secret controls - deeper Cloud Secret Detection with an analytics dashboard and alerts across all workspace types
  • BYOK encryption - protect sensitive Postman data with your own customer-managed key in AWS KMS; revoke or restore Postman's encryption permissions at any time

Quick Answers - common questions▶
  • "Why is Free only 1 user now?" - Free is now a complete single-developer experience (unlimited runs, Git, mocks, 50 AI credits) rather than a light 3-person team plan. Collaboration starts at Team, which is actually built for multi-user work with real roles and controls.
  • "What's the real difference between Team RBAC and Enterprise RBAC?" - Team RBAC is workspace-level, the same as the old Professional plan. Enterprise RBAC is org-wide and advanced - user groups, API-level roles, governance and network manager roles.
  • "Why did add-ons mostly go away?" - They caused constant confusion about which plan someone actually needed. Almost everything is now bundled directly into the plan it belongs to, unlimited, so the purchase decision is just "which plan," not "which plan plus which add-ons."
  • "Are AI credits really unlimited?" - No plan is unlimited, but each has a real baseline most users never hit, and consumption pricing only kicks in above that - it's a safety valve, not the default experience, and admins choose whether overage billing is even turned on.
